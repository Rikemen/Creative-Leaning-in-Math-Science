## ゴール・対象範囲

`1_27_置換/Permutation.js` に、Matrix に依存しない `Permutation` クラスを実装する。README の #48 に記載された7項目を、`sketch.js` の実行例で順に確認できることを完成条件とする。

## 前提・リスク・仕様

### 現状確認（2026-09-18）

- `Matrix.js` は行列演算、消去法、ランク、連立方程式を実装している。
- `sketch.js` は `setup()` で連立方程式の例をコンソール出力し、`draw()` で背景を描く。
- `index.html` は p5.js と各 JS を通常の script タグで読み込む。画面遷移はなく、単一ページで動作する。
- 対象ワークスペース内に既存の package.json やテスト基盤は見つからなかった。確認した Node.js は v22.23.1。
- 現在のブランチは `dev`。README などに作業中の差分があるため、実装開始時にも再確認し、その内容を保持する。

### API と数学上の約束

| API（新規予定） | 仕様 |
| --- | --- |
| `new Permutation(images)` | `[2, 3, 1]` は 1→2、2→3、3→1。長さ n の配列に 1〜n が一度ずつ現れることを検証 |
| `size` | 読み取り専用の次数 n |
| `apply(i)` | 整数 i∈{1,…,n} の行き先を返す |
| `toArray()` | `[σ(1),…,σ(n)]` のコピーを返す |
| `Permutation.identity(n)` | 恒等置換を生成 |
| `sigma.compose(tau)` | σ∘τ を新規生成。`sigma.apply(tau.apply(i))`。同じ次数が必要 |
| `sigma.inverse()` | 逆置換を新規生成 |
| `Permutation.cycle(n, elements)` | 指定順に巡回し、最後から先頭へ戻る。指定外の要素は固定 |
| `Permutation.transposition(n, a, b)` | 異なる2要素の互換。内部で `cycle(n, [a, b])` を利用 |
| `sigma.sign()` | 転倒数 I に対して `(-1)^I`。戻り値は +1 または -1 |
| `sigma.isEven()` / `sigma.isOdd()` | `sign()` が +1 / -1 かを返す |

- 教材では n は1以上の整数とし、空配列の置換は拒否する。n=0 の置換は数学的には定義可能だが、この教材の API 範囲に含めない。
- `cycle` の要素は1個以上、重複なし、1〜n の整数とする。1要素の巡回は恒等置換。空配列は拒否する。
- 入力配列と返却配列はコピーする。内部対応は private field に保持し、合成・逆置換で元の置換を変更しない。
- 型の不一致（配列でない、数値でない、合成相手が置換でない）は `TypeError`。数値の非整数・範囲外・NaN・Infinity、空配列、重複、次数不一致は `RangeError` とする。疎配列も拒否する。
- `sigma(1)` という callable なオブジェクトにはしない。冒頭の教材例で `const sigmaFunction = (i) => sigma.apply(i)` と対応を示し、数学の「関数」とクラス表現を結び付ける。
- 符号は初学者が追える O(n²) の転倒数で計算する。巡回分解による高速化やキャッシュは追加しない。

### 実行方式と規約

ブラウザ側は既存の通常 script と p5.js の `setup` / `draw` を維持する。新規クラスに `require` / `module.exports` は追加しない。テストは `.mjs` とし、`import` で Node.js 標準機能を使う。`node:vm` の独立したコンテキストで `Permutation.js` を実行し、同じコンテキストからクラスを取得して検証する。これにより教材全体を ESM に移行せず、ブラウザで読むソースそのものを検証できる。

VM 境界では配列や Error の prototype が異なるため、配列はテスト側の `Array.from` で比較し、例外は `name` と内容で確認する。テスト用の VM 設定は必要最小限とする。

参照規約はリポジトリ直下の `.agent/rules/esm-compatibility.md`、`language-strategies.md`、`senior-engineer-conduct.md`、`lint-after-code-change.md`。本計画では新規パッケージの導入、CSS 変更、デプロイ、コミットを含めない。TS/Vue を対象とする既存 lint 規約の適用ファイルも変更しない。

## 詳細 Loop

各 Loop では「失敗するテスト追加 → 最小実装 → 対象テスト実行 → 必要な整理 → 整理した場合は再実行」の順を守る。すべて15分以内を目安とし、超えそうな場合は機能を増やさず分割する。CSS は全 Loop で変更不要。

### Loop 1：置換の表現と適用

- **目的:** 数学の対応表をコード上の関数として扱う。
- **先に書くテスト:** `[2,3,1]` の入力1〜3の結果が2,3,1。`[1]` の適用。空・重複・疎配列・型違い・非整数・範囲外の拒否。入力配列や `toArray()` の返却値を書き換えても元の対応が変わらない。
- **最小実装:** VM でソースをロードするテスト準備、constructor、`size`、`apply`、`toArray` を追加する。検証時は疎配列の穴も検出する。
- **実行:** `node --test 1_27_置換/tests/permutation.test.mjs`
- **整理:** 1始まりから0始まりへの変換を `apply` 内に集約。内部状態を不用意に公開しない。
- **完了条件:** 正しい対応が得られ、不正な置換を生成できない。

### Loop 2：恒等置換

- **目的:** 合成と逆置換の基準となる置換を用意する。
- **先に書くテスト:** `identity(1)` → `[1]`、`identity(4)` → `[1,2,3,4]`。0・負数・小数・NaN・Infinity・数値以外の拒否。
- **最小実装:** 正の整数 n を検証して1〜nの配列から生成する。
- **実行:** `node --test 1_27_置換/tests/permutation.test.mjs`
- **整理:** 次数の検証を後続の生成メソッドでも使える小さな内部処理にする。
- **完了条件:** 各要素をそのまま返す恒等置換が生成できる。

### Loop 3：合成

- **目的:** 関数合成の順序を実装と例で固定する。
- **先に書くテスト:** σ=`[2,1,3]`、τ=`[1,3,2]` に対し σ∘τ=`[2,3,1]`、τ∘σ=`[3,1,2]`。左右の恒等置換、次数不一致と型違いの拒否、元の2つの配列が変わらないこと。
- **最小実装:** 各 i に `this.apply(other.apply(i))` を適用した配列から新しい置換を作る。
- **実行:** `node --test 1_27_置換/tests/permutation.test.mjs`
- **整理:** 「右側から先に作用する」コメントと JSDoc を揃える。
- **完了条件:** 合成の順序を逆にしたとき、上記の異なる結果が得られる。

### Loop 4：逆置換

- **目的:** 対応を逆転し、元へ戻す操作を作る。
- **先に書くテスト:** `[2,3,1]` の逆が `[3,1,2]`、σ∘σ⁻¹とσ⁻¹∘σが恒等置換、逆の逆が元の置換。元の配列が変わらないこと。
- **最小実装:** `inverse[σ(i)-1] = i` で逆対応を作る。
- **実行:** `node --test 1_27_置換/tests/permutation.test.mjs`
- **整理:** 数学の i と内部添字の区別をコメントで明示する。
- **完了条件:** 左右どちらから合成しても元に戻る。

### Loop 5：巡回置換

- **目的:** 巡回記法から対応を生成する。
- **先に書くテスト:** `cycle(4,[1,3,2])` → `[3,1,2,4]`。末尾2→先頭1、固定点4→4、1要素の巡回、要素の重複・空・範囲外・型違いと不正な n の拒否。
- **最小実装:** 恒等対応を作り、指定要素だけ次の要素へ写す。末尾は先頭へ戻す。
- **実行:** `node --test 1_27_置換/tests/permutation.test.mjs`
- **整理:** 巡回生成を、既存の入力検証と重複しすぎない構成にする。
- **完了条件:** 巡回の向きと固定点が正しい。

### Loop 6：互換

- **目的:** 2要素の交換をわかりやすい API にする。
- **先に書くテスト:** `transposition(4,1,3)` → `[3,2,1,4]`。自分自身との合成が恒等置換。同一点指定、不正な n・a・b の拒否。
- **最小実装:** `cycle(n,[a,b])` に委譲する。
- **実行:** `node --test 1_27_置換/tests/permutation.test.mjs`
- **整理:** 交換処理と検証を二重実装しない。
- **完了条件:** 2要素だけが交換され、2回適用すると元に戻る。

### Loop 7：置換の符号

- **目的:** 転倒数と符号の関係を実装する。
- **先に書くテスト:** 恒等置換は+1、互換は-1、`[2,3,1]` は+1、`[3,2,1]` は-1。長さ2・3・4の巡回はそれぞれ-1・+1・-1。
- **最小実装:** i<j かつ σ(i)>σ(j) となる組を数え、偶数なら+1、奇数なら-1を返す。
- **実行:** `node --test 1_27_置換/tests/permutation.test.mjs`
- **整理:** なぜこのカウントで符号が求まるか、README に載せる説明とコメントを一致させる。
- **完了条件:** 既知の具体例と k-cycle の符号 `(-1)^(k-1)` に一致する。

### Loop 8：偶奇判定と代数的性質

- **目的:** 偶置換・奇置換の判定を完成させ、機能間の整合性を検証する。
- **先に書くテスト:** 恒等置換と3-cycleは偶、互換と4-cycleは奇。各例で `isEven()` と `isOdd()` が反対の真偽値になる。
- **最小実装:** `sign() === 1` / `sign() === -1` を使う。
- **追加検証:** テスト内に S₃ の6通りを明記し、左右の逆、符号の逆置換との一致、全36組の符号の乗法性、全216組の結合法則を確認。置換を列挙する本番 API は追加しない。
- **実行:** `node --test 1_27_置換/tests/permutation.test.mjs`
- **整理:** 判定ロジックを `sign()` に集約し、テスト名を数学の性質が読める名前にする。
- **完了条件:** 偶奇の例と代数的性質がすべて成立する。

### Loop 9：教材への接続と説明

- **目的:** README の7項目をブラウザで一通り実行できるようにする。
- **先に書くテスト:** `lesson.test.mjs` の VM で `Permutation.js` と実際の `sketch.js` を読み込み、p5.js の最小スタブで `setup()` を実行する。`console.log` の捕捉で、対応・合成・逆・巡回・互換・符号・偶奇の既知の結果が出力されることを確認する。ログ全文のスナップショットやソース文字列の一致には依存しない。
- **最小実装:** 既存の連立方程式の例を置換の例に置き換える。冒頭に `sigmaFunction(i)` の例を置き、その後に各 API を順に実行する。index の script を更新し、README にコマンドと期待結果を追記する。
- **実行:** `node --test 1_27_置換/tests/permutation.test.mjs 1_27_置換/tests/lesson.test.mjs`
- **整理:** 計算はクラス、教材の表示は sketch に置く。説明用の値には短い名前と日本語コメントを付ける。p5.js の背景表示は維持する。
- **完了条件:** 自動テストに加え、実ブラウザで JS の読み込み・setup の実行・全項目の結果を確認できる。

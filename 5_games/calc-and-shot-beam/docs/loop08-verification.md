# Loop 08 カメラ接続の検証

2026-09-11。ローカル `http://127.0.0.1:5100/` で検証。今回の変更は未デプロイ。

## 実装範囲

- `public/js/input/camera.js`：映像のみの取得、準備状態、30秒の初期化／推論タイムアウト、停止、接続切れ、遅延完了の破棄。
- `public/js/input/body-pose.js`：カメラ操作時だけml5.js 1.3.0を読み込み、MoveNet SINGLEPOSE_LIGHTNINGを非同期起動。単発の `detect(video)` を直列に実行するため、推論失敗を捕捉でき、実行中の推論完了を待ってモデルを破棄できる。
- `public/js/ui/camera-panel.js`：準備・成功・失敗理由・再試行・停止・タッチ切替・映像プレビュー・姿勢検出状態。
- `public/js/ui/game.js`：カメラ確認前にゲームを停止。タッチ切替でカメラを終了し、停止していた問題・HP・得点・残り時間から再開。プレイ中の「タッチであそぶ」ではゲームを初期化しない。
- タブ非表示・ページ離脱・結果への遷移でも停止する。マイク、録画、映像アップロードは実装していない。

Loop 08はカメラ接続確認と姿勢取得まで。ゲーム操作は引き続きタッチ／マウス／キーボード。身体で狙う／撃つ操作、姿勢の整形、認識喪失からのゲーム復帰はLoop 09以降。

## ブラウザ検証

Chrome headless＋Playwright、Chromeの模擬映像デバイスを使用。ml5とMoveNetはモックに置き換えず、外部配布先から読み込んだ実物を使用した。

1. p5 2.2.2のキャンバス表示。カメラ操作前にml5への取得通信がない。
2. カメラ操作→映像取得→ml5 1.3.0とMoveNet取得→最初の推論完了→「カメラの準備ができました！」。
3. 「タッチであそぶ」後に全MediaStreamTrackが `ended`、ゲーム開始、正解カードの保持で1点。
4. 進行中に許可拒否を注入してカメラ操作。案内と再試行ボタンが表示され、待機中の時計が停止。
5. タッチへ戻っても問題と得点1が維持され、プレイ画面へ復帰。
6. 1280×900の成功表示と390×844の拒否表示を目視確認。狭幅で横スクロールなし。
7. ページ例外0件。観測した通信は全てGETで、ページ・ライブラリ・モデルの取得。モデル取得にはtfhub.dev→kaggle.com→storage.googleapis.comのリダイレクトが含まれる。

記録：[ブラウザ結果](loop08-browser-results.json)、[PC成功表示](loop08-camera-pc.png)、[モバイル幅の拒否表示](loop08-camera-denied-mobile.png)。画像の緑色プレビューは模擬映像。モデル配信の署名付きクエリは記録から除いた。

**未確認**：物理Webカメラの起動、本人の姿勢検出精度、OSのカメラ許可画面、実スマートフォン／iPad、子供の試遊、公開環境。模擬映像による実モデルの推論成功は、実カメラでの人物認識確認とは区別する。

## 手元での確認

1. `npm run dev` で起動し、`http://127.0.0.1:5100/` を開く。既に同じサーバーが動いていればそのまま利用する。
2. 「カメラをためす」→ブラウザで許可→映像と準備完了表示を確認。身体を映し「からだが見つかったよ」を確認する。
3. 「カメラを止める」でブラウザのカメラ使用表示が消えることを確認。再試行後にタブを隠した場合も確認する。
4. タッチで1点取り、再度カメラを試す。準備中に残秒が減らず、タッチへ戻ると同じ問題と得点から続けられることを確認する。
5. カメラを拒否した場合にも、理由と「もう一度ためす」「タッチであそぶ」が表示され、カードで遊べることを確認する。

今回使用したポート5100のサーバーは作業前から存在していたため停止していない。

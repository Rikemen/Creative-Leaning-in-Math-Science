# Loop 26〜29 検証記録

実施日：2026-09-14。Loop 26〜28は実装・自動検証済み。Loop 29はPC Chromeの代替操作を計測し、物理カメラによる確認は残件とする。親子試遊はユーザー指示によりスキップ。未デプロイ。

## 変更

- Loop 26：セッションに停止理由を保持。手動、非表示、フォーカス移動、ページ離脱、カメラ停止・準備、認識喪失を区別する。最初の停止理由を重複イベントで上書きせず、問題・HP・得点・残り時間と破壊演出の残り時間を保持。イベント時に表示と音の状態を即時同期する。
- Loop 27：停止ボタンを44×44 CSS pxにし、縦画面のHUDを拡張。式・時間ゲージ・カードを下へ調整し、停止ボタンとの重なりを解消。ヒーローの体を腕より前に描く順序は維持。
- Loop 28：`tests/e2e/`、共通fixture、Playwrightローダー、`test:e2e`を追加。一時サーバーを自動で起動・終了し、時計と姿勢のモックはテスト内に限定。
- Loop 29：`tests/performance/desktop.cjs`と`test:performance`を追加。60秒×3回を実時間で実行し、ロード・描画間隔・キーボードから表示までの遅延・終了時の音停止をJSONへ記録する。

## 自動検証

`npm test`：80件成功。停止理由7種類、重複停止、停止時間の除外、破壊中の停止・再開、初期化、画面領域を含む。

`npm run test:e2e`：6件成功。[機械可読結果](loop28-e2e-results.json)。

1. 誤答でHP不変→正解で破壊→離して次問→時間切れ→出題範囲を変更して再プレイ。
2. 非表示→フォーカス移動の重複停止、時間・HP・得点維持、音停止、再表示だけでは再開しないこと、再開時の入力解除、ページ離脱。
3. カメラ許可拒否からタッチへ戻り、途中の問題・HPを維持。
4. 1280×720、1024×768、844×390、390×844、320×740で数字18・カード領域・停止ボタン・停止ダイアログを検証。
5. CDPのタッチ入力で正解を破壊し、停止中の縦横変更後も進行を保持。
6. 合成カメラ・模擬姿勢で認識喪失→停止→腕をほどいて3秒→復帰→新しい発射を検証。カメラ停止後のトラック解放も確認。

画面記録：[390px](loop27-390.png)、[844px](loop27-844.png)。数字とカードの収まりを目視確認。CDPによるタッチ、合成映像、模擬姿勢は物理端末・人物の確認とは区別する。

## 性能計測の条件と限界

インストール済みChromeのheadless、1280×720、キーボードによる代替操作、実音源有効。ローカルHTTP配信でキャッシュのない新規ブラウザページを使用。時計の置換・姿勢のモックは使用しない。ブラウザ版・CPU・OS・メモリは[計測JSON](loop29-performance.json)に記録する。

描画回数はゲーム用canvasのclearRectを数える。p5の設定目標は30fps。入力遅延はキーイベントから命中フィードバックDOM更新までであり、画面への実表示やカメラ推論時間を含む身体応答ではない。初回素材準備時間にはテスト側の状態確認待ちも含む。ローカル転送結果を公開ネットワークのロード時間には一般化しない。

実カメラでの初期化・60秒連続認識・身体応答250ms以内、iPad Safari、実機の音量・聴感は未確認。Loop 29全体を完了とは扱わない。計測の再現方法と必要な既存ランタイムは[tests/README.md](../tests/README.md)を参照。

## 手元で確認

ローカルサーバー起動中なら http://127.0.0.1:5100/ を再読み込み。「はじめる」→カードを長押し→一時停止で理由を表示→「つづける」で同じ問題へ戻る。画面を狭くしても停止ボタンを押せることを確認する。起動が必要ならプロジェクト内で `npm run dev`、停止はCtrl+C。

# Loop 11 発射ポーズ

2026-09-11。ローカル `http://127.0.0.1:5100/` で検証。未デプロイ。

## 実装

- `public/js/input/gesture.js`：肩・肘・手首を肩幅単位で判定。左右の手首がそれぞれ胸の中央を越え、胸付近にある状態を腕組みとする。左右反転・左右どちらの腕が上の場合も許容。指の形は使わない。欠けた関節や不正座標は「不明」とする。
- `GESTURE_SETTINGS` に閾値を集約。手首yは肩中心から-0.15〜0.9肩幅、肘yは0〜1.2、交差余裕は0.05。実人物の姿勢や遮蔽に合わせた調整は未実施。
- 推論開始時刻で250ms以上継続した腕組みだけが発射になる。同一結果を描画のたびに数えず、短い誤検出、250ms以上の結果の間隔、古い結果は保持時間を積み上げない。
- `public/js/input/body-input.js`：照準と発射状態を既存のGameSessionのpress/move/releaseに変換。開始・停止・認識喪失後は有効な「腕をほどいた姿勢」を確認してから発射。次の問題では腕をほどくまで新たなpressを出さない。
- `ui/aim-practice.js`／`camera-panel.js`／`game.js`：校正と練習後に「カメラで はじめる・つづける」で本番を開始／再開。実ゲームの4択に照準を表示し、正解はHP減少・破壊で1点、誤答はバリア。ポインター／キーボードの発射入力はカメラプレイ中には受け付けない。
- カメラ停止・カメラ障害はゲームを一時停止。タッチ切替時は映像を解放し、問題・HP・得点を保持して再開する。結果画面でもカメラを停止。

認識不明時には発射を止めるが、その間の時計は進む。長い認識喪失での自動一時停止、復帰準備、再開カウントダウンはLoop 12。

## 検証

`npm test`：**55件成功**（従来47件＋発射・身体入力8件）。左右対称、腕の上下、腕をほどいた状態、頭上／胸より下の手、欠けた関節、250ms保持、短い検出・重複・古い／未来／不正時刻、解除、再発射、誤答、照準移動中のHP、次問への持越し禁止、認識喪失後の解除要求、終了後の得点禁止を確認。

Chrome headless＋Playwrightで、合成映像と模擬姿勢を既存画面へ入力した。ブラウザ検証では以下を確認：

1. 中央登録→カメラ開始。カメラプレイ中に正解へSpaceを保持しても得点しない。
2. 誤答へ照準を合わせて腕組み→バリア・0点。
3. 腕組みを保持したまま正解へ移動→破壊・1点。
4. 次問の正解を狙って保持しても1点のまま。一度腕をほどいて再度組むと2点。
5. 未検出を挟み、腕を組んだまま認識が戻っても2点のまま。
6. カメラ停止で一時停止し、残秒不変。タッチ切替で問題・得点を維持して再開、映像トラックは全て `ended`。タッチ側の正解操作で3点。
7. ページ例外0件。ゲーム画面を目視確認。

[ブラウザ結果](loop11-browser-results.json)、[身体操作で2枚破壊した画面](loop11-body-game.png)。

**未確認**：物理カメラでの腕組み認識、腕の遮蔽や子供の体格への適合、実スマートフォン／iPad、公開環境。今回のブラウザ検証ではml5の出力を模擬しており、実モデルの姿勢精度を保証しない。

## 手元で確認

`npm run dev` → `http://127.0.0.1:5100/` →「カメラをためす」→ 許可 → 肩を映して中央登録 →「カメラで はじめる・つづける」。一度腕をほどき、左右に動いて答えを狙い、胸の前で腕を組んで保持する。次問は腕をほどいてから再度組む。

単体は `node --test tests/unit/gesture.test.js`。ChromeとPlaywrightのある環境で `node tests/browser/pose-preview.cjs <Playwrightのモジュールパス> --gesture` を実行するとブラウザ検証を再現できる。今回は既存ランタイムとローカルサーバーを利用し、依存インストールやサーバー停止は行っていない。

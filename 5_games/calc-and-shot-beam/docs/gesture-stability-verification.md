# 手首判定の安定化

確認日：2026-09-14。ローカル実装。未デプロイ。

## 再現できた問題と変更

従来は手首が1フレーム欠けただけで発射準備が完全に解除されていた。手首が戻り、発射の形を250ms保持しても、大きく離し直すまでゲームでは発射しなかった。

手首が見えない間は即座にビームを止める。同じ問題の中で既に発射準備を済ませている場合に限り、500ms以内の手首欠損では準備状態を保持する。手首が戻った後は新しい認識結果で再度250ms保持すると発射する。500ms超の欠損、肩の喪失、停止、問題切替では準備を破棄し、一度手首を離す必要がある。欠損座標を補完して発射する処理は追加していない。

また、カメラ推論の完了後に常に80ms待つ構成を変更した。推論開始から80msを目安に次の推論を開始し、処理が80ms以上かかった場合は追加で待たない。推論は重複させず、撮影時刻と250msの鮮度条件は維持する。これはスケジューリングの修正であり、実カメラの速度改善量は未計測。

## 設定画面

「ビームの出しやすさ」を追加。手首間の直線距離を肩幅で正規化し、次の範囲で判定する。

| 設定 | 発射準備を始める距離以下 | 離したと判断する距離以上 |
| --- | ---: | ---: |
| ふつう（既定） | 0.65 | 0.90 |
| ゆったり | 0.90 | 1.15 |
| しっかり近づける（従来相当） | 0.45 | 0.65 |

境目では直前の状態を保持し、判定のちらつきを抑える。感度変更時は保持途中の判定をリセットする。中央登録と感度設定は独立し、感度だけ変えても中央を登録し直す必要はない。設定した感度はゲーム画面と骨格の手首間ラインにも適用し、同じページ内で再設定するときも保持する。

設定画面に両手首・片方の手首・肩の欠損を区別した案内と、手首の近さを表示する。「発射の形を認識」と実際のゲームの発射準備を区別し、開始や次問では引き続き一度手首を離す。

[1280×720の設定画面](gesture-settings-1280.png)。戻るボタンを見出し右へ移し、調整項目を追加しても16:9画面内で操作できる配置を維持した。

## 検証

- `npm test`：89件成功。感度境界・変更時の保持リセット、短い欠損中の無加点と復帰、長い欠損・停止・問題境界での自動発射防止、推論時間を含めた次フレームの間隔を確認。
- ブラウザ検証：19件すべて成功。新しい手首判定2件と設定・起動・骨格表示・TV配置の10件、通常プレイと実時間60秒のカメラ再プレイを含む7件を分けて実行。
- `gesture-stability.test.cjs`：距離0.7で厳しい設定では停止、ゆったり設定では発射の形として認識すること、設定のゲームへの適用と得点を確認。
- 模擬カメラで短い手首欠損中のHP停止、復帰後に手首を離さず同じ問題へ再発射、700ms超の欠損後は離し直す必要があることを確認。
- 1280×720・1366×768・1920×1080の配置、設定画面とゲームの分離、開始・再開・骨格表示切り替えを確認。

テストには合成映像と模擬姿勢を使用。手が重なった実人物の認識精度、照明や距離の違い、実機推論速度は未確認。親子試遊はユーザー指示によりスキップ。

## ローカルでの確認

`http://127.0.0.1:5100/` を再読み込みし、「カメラ設定」で手首の案内を確認する。目印が両方見えているのに発射の形になりにくい場合は「ビームの出しやすさ」を「ゆったり」にする。片方が見えない場合は両手首が見えるように手を少しずらし、練習カードの発射表示を確認してからゲームへ進む。

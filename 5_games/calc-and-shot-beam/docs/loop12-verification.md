# Loop 12 認識の復帰

2026-09-11。ローカル `http://127.0.0.1:5100/`。未デプロイ。

## 変更

`public/js/input/recovery.js` に追跡・認識喪失・復帰待機・3秒カウントダウンを集約し、`ui/game.js` から利用する。`RECOVERY_SETTINGS` は喪失1000ms、再開3000ms。`aim-practice.js` が返す制御情報に姿勢の推論開始時刻を含め、250ms以上古いものを有効な認識として使わない。

- 短い認識喪失は発射だけを止め、時計は継続。認識が戻っても腕をほどくまで発射しない。
- 喪失が1秒続くと、問題・HP・得点・残り時間を保持して自動一時停止。
- 校正済みで肩・肘・手首が映り、腕をほどいた状態が3秒続くと再開。再喪失・腕組み・大きなサンプル間隔でカウントダウンを最初からやり直す。
- 再開直前の姿勢では発射入力を有効化しない。再開後の新しい腕解除サンプルを確認してから腕組みで発射する。
- 手動停止後にカメラで続ける場合も同じ待機・カウントダウンを通る。「休む（自動再開を止める）」、カメラ停止、非表示、タッチ切替で復帰状態を破棄。再開用の非同期タイマーは使用しない。
- 描画フレームが大きく遅れた場合は、最後の姿勢の鮮度期限で入力を解除し、喪失期限で停止する。次のフレームで新しい姿勢が得られていても、間の古い入力でダメージを積み上げない。停止・タッチ切替イベントでも先に鮮度を確認する。

## 確認結果

`npm test`：**62件成功**（前回55件＋復帰7件）。短い喪失、1000ms境界、HP・問題・得点・時間保持、カウントダウン、新しい入力、再喪失、取消、古い／未来の時刻、手動再開を検証。描画が5秒遅れた例では古い姿勢の有効期間250ms分だけのダメージに制限され、得点0・経過1350msで停止することを確認した。

Chrome headless＋Playwrightの合成映像・模擬姿勢で、以下を確認した。

1. 正解に途中までダメージを与えたあと認識を失わせ、自動一時停止。問題・途中のHP・得点0・残り時間を保持。
2. 腕組みで戻っても待機。腕をほどくと3秒カウントダウン。途中の再喪失で中断し、新たに3秒から開始。
3. 再開後も問題・HP・得点を保持。新しい解除姿勢を確認後に腕を組むと破壊し1点。
4. 再び復帰待機に入り、カウントダウンを手動で取り消すと3秒以上経過しても再開しない。
5. 手動停止後にカメラ再開のカウントダウンへ進み、タッチへ切り替えるとカメラを解放。同じ得点でゲームを継続し、遅れた自動再開は発生しない。

[ブラウザ結果](loop12-browser-results.json)、[カウントダウン画面](loop12-countdown.png)。実人物映像は使用していない。

検証途中、カウントダウン終了直後に模擬姿勢を腕組みに切り替えると、新しい解除サンプルがないため発射しないことを確認。テストを実仕様に合わせ、新しい解除サンプルの確認を待ってから発射するようにした。

**未確認**：実カメラの認識喪失・復帰速度、子供の操作性、実スマートフォン／iPad、公開環境。これらはLoop 13の試遊で確認する。

## 手元で確認

`npm run dev` → `http://127.0.0.1:5100/` → カメラ許可・中央登録 → カメラで開始。途中で肩や腕を画面から外し、約1秒後に時計が止まることを確認する。肩・肘・手首を戻して腕をほどくと3秒で再開する。途中で再び隠す、休む、タッチに切り替える操作も確認する。

単体：`node --test tests/unit/recovery.test.js`。ChromeとPlaywrightのある環境で `node tests/browser/pose-preview.cjs <Playwrightのモジュールパス> --recovery` を実行するとブラウザ検証を再現できる。今回も既存のランタイムとサーバーを使用し、インストール・デプロイ・サーバー停止は行っていない。

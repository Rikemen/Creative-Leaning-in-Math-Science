# Loop 10 照準

2026-09-11。ローカル `http://127.0.0.1:5100/` で確認。未デプロイ。

## 実装

- `public/js/input/aim.js`：中央校正時の両肩中心と肩幅を保存し、鏡写し画像上の横移動から0〜3のカード番号を返す。腕・手首・答えの値を参照しない。校正後は肩幅の瞬間的な変化で感度が動かないよう、校正時の肩幅を使用する。
- `AIM_SETTINGS`：標準は左右それぞれ肩幅の0.5倍の移動で全範囲。「小さく」は0.25倍、「大きく」は1倍。設定変更後は再校正が必要。中央位置は4枚の境界にあるため、初回は右寄りの3枚目を選ぶ。
- 横位置 = `clamp(0.5 + (現在の肩中心x − 校正中心x) / (2 × 校正肩幅 × 片側範囲), 0, 1)`。100msの時定数で指数平滑化し、推論開始時刻の差から係数を計算する。同じ姿勢サンプルを描画フレームごとに繰り返し平滑化しない。
- 4等分した領域に吸着。隣へ移るには境界を全体幅の0.04だけ越える必要があり、境界上の小さな揺れで往復しにくい。動きが大きい場合は複数カードを飛び越えて移動可能。
- 無効・250ms以上古い姿勢では照準を消す。有効な肩が戻ったら、保存済みの中央位置で照準を再開する。カメラ停止・再試行では校正も破棄する。本番ゲームの認識復帰処理はLoop 12の範囲。
- `public/js/ui/aim-practice.js`：カメラ準備完了後に1〜4の練習カード、中央登録、範囲設定、照準マークを表示。肩を取得できない間は中央登録を無効化。照準を数字の下に表示し、数字を隠さない。
- 練習中は既存のカメラ準備と同様にゲームが停止している。ゲーム判定・HP・得点には入力しない。「タッチであそぶ」でカメラを終了して元のゲームに戻る。

今回の仮画面は照準だけを練習するための4枚。問題の正解を示すものではない。ポーズによる発射とゲームへの接続はLoop 11。

## 確認結果

テストを先に追加し、未実装による失敗を確認してから実装した。`npm test` は **47件成功**（前回39件＋照準8件）。中央校正、4枚への到達、腕の座標に依存しないこと、身体サイズの違い、両方向の境界保持、平滑化の時間依存性、重複・逆順・古い・不正な姿勢、喪失、再校正、範囲設定を検証した。

Chrome headless＋Playwright、Loop 09の合成映像と模擬姿勢を再利用。本番コードへの検証用入力は追加していない。

1. 校正前はどのカードにも照準を表示しない。
2. 通常ゲームで1点取得してからカメラを開始。中央登録後、両手首を胸前で交差させた模擬姿勢のまま肩を左右へ動かし、1〜4の全カードを選択できた。
3. 範囲を「小さく」に変更すると校正が解除され、再登録後は半分の移動量で両端へ到達した。
4. 未検出で照準が消え、有効姿勢で戻る。推論を600ms遅延させた場合も古い照準が消えた。
5. 練習前後で得点1・問題・残り時間を保持。タッチ復帰後も同じ問題から再開し、全映像トラックが `ended`。遅い推論が返っても照準は復活しない。
6. 1280×900と390×844で画面を目視。4枚は横一列で、横はみ出しなし。ページ例外0件。

## 手元で確認

`npm run dev` → `http://127.0.0.1:5100/` →「カメラをためす」→ 許可 → 肩を映す →「ここをまんなかにする」。少し左右へ移動して4枚の照準を確認する。腕を組んだ状態でも試し、必要なら「動くはんい」を変更して中央を登録し直す。「タッチであそぶ」でゲームに戻れる。

単体は `node --test tests/unit/aim.test.js`。ブラウザはChrome・Playwrightがある環境で `node tests/browser/pose-preview.cjs <Playwrightのモジュールパス> --aim`。プロジェクトでPlaywrightが解決できる場合、モジュールパスには `playwright` を指定できる。今回は既存の同梱ランタイムとポート5100のサーバーを使用し、インストールやサーバー停止は行っていない。

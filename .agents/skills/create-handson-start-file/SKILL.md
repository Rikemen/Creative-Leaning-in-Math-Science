# ハンズオン用ファイル一式作成スキル (Handson Files Creation)

**トリガー:** 
ユーザーから「ハンズオン用のカンペ（HTML）を作成して」「インクリメンタルな実装計画を立てて」といった、**ライブコーディングやハンズオンを前提としたタスク**を依頼された場合。

**目的:** 
ハンズオンを実施する際、本番環境のコード（例: 直下の `Matrix.js` など）を直接汚さず、専用の `handson/` フォルダ内に「開始時のコード」「完成後のコード」「カンペ」の3点セットを分離して準備すること。

## 実行ルール

1. **`handson/` フォルダの作成**:
   対象となるプロジェクトディレクトリ内に `handson/` ディレクトリが存在しない場合は作成します。

2. **3点セットの作成**:
   本番のコードを直接編集するのではなく、`handson/` フォルダ内に以下のファイルを準備して、そちらで作業を進めてください。

   - **`start_[元のファイル名]` (開始用コード)**:
     エージェントが実装を加える前の初期状態のコード。既存ファイルをコピーするか、新規の場合は空枠やボイラープレートを作成します。
     *例: `cp Matrix.js handson/start_Matrix.js`*

   - **`end_[元のファイル名]` (完成用コード)**:
     エージェントが最終的に実装を完了させた状態のコード。ハンズオンのゴールとして機能します。
     *例: `cp Matrix.js handson/end_Matrix.js` とした後、エージェントはこの `end_Matrix.js` を編集して実装を完成させます。*

   - **`[カンペ名].html` (カンペHTML)**:
     プレゼンターがライブコーディングを進めるためのトークスクリプトとコードスニペットをまとめたHTMLファイル。これも `handson/` フォルダ内に生成します。

3. **計画（/plan）への組み込み**:
   `/plan` ワークフローで実装計画を立てる際、「提案される変更ファイル」には本番のコードではなく、この `handson/` フォルダ内の `start_`, `end_`, カンペファイルが作成・編集される旨を明記してください。

4. **ユーザーへの案内**:
   タスク完了時や計画提示時に、「本番コードは変更せず、`handson/` フォルダ内に一式（start, end, カンペ）を用意します」と案内してください。

## 注意事項
- サンドボックスの制約によりエージェント側で直接 `cp` コマンドが実行できない場合は、ユーザーに実行を依頼するコマンドを提示するか、`read_file` して新しいファイルとして `write_to_file` する方法で確実に対応してください。

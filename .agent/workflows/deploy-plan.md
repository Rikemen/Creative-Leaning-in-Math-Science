# Deploy Command Planner (日本語)

**トリガー:** `/deploy-plan`

**説明:**
直近の変更内容（コミットや差分）を分析し、プロジェクト内のどの領域（フロントエンド、Cloud Functions、Firestore ルールなど）が更新されたかを自動判定します。
その結果に基づいて、必要となるビルドコマンドおよび `firebase deploy` コマンドを組み立て、ユーザーがターミナルにコピー＆ペーストしてそのまま実行できる形式で提示します。

> **⚠️ 注意:**
> エージェント環境（サンドボックス）では `firebase deploy` などの外部へのデプロイ操作が制限されているため、**エージェント自身はデプロイを実行せず、コマンドの提示のみを行います。**

---

## 1. 変更内容の分析
- **目的:** どのリソースをデプロイする必要があるかを特定する。
- **アクション:**
  - `git status` や `git diff --name-only HEAD~1` （または直近の関連コミット）を確認し、変更されたファイルのパスを調査する。
  - 以下の基準でデプロイ対象のターゲット（`--only` で指定するもの）を判定する:
    - `src/`, `public/`, `index.html`, `vite.config.ts` など → **Hosting**（フロントエンド）
    - `functions/` 配下のファイル → **Functions**
    - `firestore.rules`, `firestore.indexes.json` → **Firestore** (rules, indexes)
    - `storage.rules` → **Storage**

## 2. デプロイ計画の立案とコマンド組み立て
- **目的:** 分析結果から無駄のない最適なデプロイコマンドを生成する。
- **アクション:**
  - 特定したターゲット群をカンマ区切りでまとめ、`npx firebase deploy --only <targets>` の形式を作成する。
  - **Hosting が対象に含まれる場合:** デプロイ前にフロントエンドのビルドが必須となるため、コマンドの先頭に `npm run build` を必ず含める。

## 3. コマンドの提示（ユーザー実行依頼）
- **目的:** ユーザーが自身の環境でそのまま実行できるようにする。
- **アクション:**
  - 解析結果として「今回はどの部分（例: フロントエンドとFunctions）に変更があったため、このコマンドになります」という簡潔な理由を添える。
  - 実行用のコマンドを Bash 用のコードブロック（```bash）として出力し、ユーザーにコピー＆ペーストでの実行を依頼して終了する。

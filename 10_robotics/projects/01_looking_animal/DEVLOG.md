# DEVLOG：こちらを見る動物

1タスク **10分前後** で終わるように分けた開発タスク一覧。
上から順に1つずつ進め、終わったら `[ ]` を `[x]` にする。

## 進め方のルール

- **1タスク = 1つの「動いた！」を確認する。** 確認できたら次へ進む。
- **動いたらコミットする。** 壊しても1つ前に戻れるようにする（例: `git commit -m "T07 顔の中心座標を表示"`）。
- **詰まったら15分で切り上げる。** 何が起きたかを [notes.md](./notes.md) に書いて、ヒントを調べるか相談する。
- **ESP32 が届くまではフェーズ0〜4を進める。** 実機が必要なのはフェーズ5からだけ。

## 全体の流れ

```text
フェーズ0  準備              ブラウザにカメラ映像を出す
フェーズ1  見る              MediaPipe で人の顔の位置を取る
フェーズ2  仮想の首          画面の中の首を、生き物らしく動かす
フェーズ3  通信              WebSocket で角度を送る（代役サーバーで確認）
フェーズ4  シミュレータ      Wokwi で ESP32 のサーボ制御を書く
--------------------------- ここから ESP32 実機が必要 ---------------------------
フェーズ5  実機              ESP32 + サーボで通しで動かす
フェーズ6  仕上げ            首の機構・展示調整・動画
```

最終的なファイル配置（目安）:

```text
pc/
├── index.html         # p5.js と MediaPipe の読み込み
├── sketch.js          # メインの処理
└── mock-server/
    └── server.js      # ESP32 の代役 WebSocket サーバー
esp32/
└── looking_animal/
    ├── looking_animal.ino
    ├── secrets.sample.h   # Wi-Fi 情報の見本（Git に入れる）
    └── secrets.h          # Wi-Fi 情報の本物（Git に入れない）
```

## フェーズ0：準備（ESP32 不要）

### [x] T01 p5.js のキャンバスを表示する

- **やること**
  1. `pc/index.html` と `pc/sketch.js` を作る
  2. `index.html` で p5.js を CDN から読み込み、`sketch.js` を読み込む
  3. `sketch.js` で 640×480 のキャンバスを作り、背景色を塗る
- **完了の確認:** ブラウザで開くと、色の付いた四角が表示される
- **ヒント:** p5.js の CDN は `https://cdn.jsdelivr.net/npm/p5@1/lib/p5.min.js`

### [x] T02 ローカルサーバーで開く

- **なぜ:** カメラは `file://` で開いたページからは使えない。`http://localhost` で開く必要がある
- **やること**
  1. ターミナルで `pc/` に移動し、`npx serve .` を実行する（VS Code の Live Server 拡張でもよい）
  2. 表示された `http://localhost:3000` を Chrome で開く
- **完了の確認:** T01 と同じ画面が `localhost` の URL で表示される

### [ ] T03 Webカメラの映像を表示する

- **やること**
  1. `createCapture(VIDEO)` でカメラを取得する
  2. `capture.hide()` で HTML の video 要素を隠し、`image()` でキャンバスに描く
- **完了の確認:** キャンバスに自分が映る（初回はカメラの許可ダイアログが出る）

### [ ] T04 映像を鏡のように左右反転する

- **なぜ:** 反転しないと、自分が右に動くと映像の中では左に動き、直感とずれる
- **やること:** `translate(width, 0)` と `scale(-1, 1)` を使って映像を反転して描く
- **完了の確認:** 右手を挙げると、画面の右側の手が挙がる

## フェーズ1：見る（ESP32 不要）

### [ ] T05 MediaPipe の FaceDetector を読み込む

- **やること**
  1. `index.html` に `<script type="module">` を追加し、`@mediapipe/tasks-vision` を CDN から import する
  2. `FilesetResolver` と `FaceDetector.createFromOptions()` で顔検出器を作る
  3. 作った検出器を `window.faceDetector` に入れ、`sketch.js` から使えるようにする
- **完了の確認:** ブラウザの開発者ツール（Console）で `faceDetector` と打つと、オブジェクトが表示される
- **ヒント**
  - モデル: `blaze_face_short_range`（近距離向けの軽いモデル）
  - `runningMode: "VIDEO"` を指定する
  - p5.js は通常の `<script>`、MediaPipe は `type="module"` で読み込むため、`window` 経由で受け渡す

### [ ] T06 顔を検出して枠を描く

- **やること**
  1. `draw()` の中で `faceDetector.detectForVideo(capture.elt, performance.now())` を呼ぶ
  2. 結果の `detections[i].boundingBox` を使って、顔の位置に四角を描く
- **完了の確認:** 自分の顔に四角が付いてくる
- **注意:** 検出器の読み込みが終わる前は `faceDetector` が無い。無いときは検出をスキップする

### [ ] T07 顔の中心X座標を 0〜1 で取り出す

- **やること**
  1. `boundingBox` の `originX + width / 2` から顔の中心を求める
  2. 映像の幅で割って 0〜1 にする（左端 = 0、右端 = 1）
  3. 画面の隅に数値を表示する
- **完了の確認:** 左に動くと 0 に、右に動くと 1 に近づく
- **注意:** T04 で映像を反転したので、数値の向きが画面と合っているか確認する。逆なら `1 - x` にする

### [ ] T08 複数人いるときに1人を選ぶ

- **やること:** 一番大きく映っている顔（= 一番近い人）を選ぶ関数 `selectTargetFace()` を作る
- **完了の確認:** 2人で映ると、近い方の人にだけ枠の色が変わる
- **ヒント:** 1人で試すときは、スマホに顔写真を表示してカメラに見せるとよい

### [ ] T09 「人がいない」を判定する

- **やること:** 顔が1つも無いときに `targetX = null` とし、画面に「誰もいない」と表示する
- **完了の確認:** カメラの前から離れると表示が切り替わる

## フェーズ2：画面の中の「仮想の首」（ESP32 不要）

> サーボの代わりに画面上で首を動かし、動きの味付けをすべてここで完成させる。
> 実機より書き換え・確認が速いので、試行錯誤はこのフェーズでやり切る。

### [ ] T10 仮想の首を描く

- **やること**
  1. 画面下部に、角度 `headAngle` で回転する線（首）と円（頭）を描く
  2. `headAngle = 90` で真上（正面）を向くようにする
- **完了の確認:** 数値を手で書き換えると、首の向きが変わる
- **ヒント:** `angleMode(DEGREES)`、`translate()`、`rotate()` を使う。サーボと同じく 0〜180° で考える

### [ ] T11 顔の位置を角度に変換する

- **やること**
  1. `targetX`（0〜1）を `map()` で 30〜150° に変換して `targetAngle` にする
  2. `headAngle = targetAngle` として首を動かす
- **完了の確認:** 左右に動くと、首が自分の方を向く
- **ポイント:** 0° と 180° ちょうどはサーボの限界で負荷がかかるため、範囲を狭めている

### [ ] T12 動きを滑らかにする（平滑化）

- **なぜ:** T11 のままでは検出のブレで首がカクカク震え、機械っぽく見える
- **やること:** `headAngle = lerp(headAngle, targetAngle, 0.1)` のように、目標に少しずつ近づける
- **完了の確認:** 素早く動いても、首がなめらかに追いかけてくる
- **実験:** `0.1` を `0.02`（のんびり）や `0.3`（機敏）に変えて、性格の違いを感じてみる

### [ ] T13 見失ったら、少し待ってから正面に戻る

- **やること**
  1. 最後に顔を見た時刻 `lastSeenAt` を `millis()` で記録する
  2. 見失ってから 2秒経ったら `targetAngle = 90` にする
- **完了の確認:** 画面から消えると、首はしばらくその方向を見たままで、その後ゆっくり正面に戻る

### [ ] T14 気づくまでの「間」を入れる

- **やること:** 人が現れてから 0.5秒経つまでは首を動かさない
- **完了の確認:** カメラに入った直後、一瞬おいてから振り向く
- **ポイント:** この「間」があると、「気づいた」ように見える

### [ ] T15 パラメータをスライダーで調整できるようにする

- **やること:** `createSlider()` で「平滑化の強さ」「戻るまでの時間」「気づくまでの間」を調整できるようにする
- **完了の確認:** スライダーを動かすと、その場で動きの印象が変わる
- **記録:** 気に入った値を [notes.md](./notes.md) にメモする

### [ ] T16 コードを整理する

- **やること:** `sketch.js` を役割ごとの関数に分ける
  - `detectFace()`: 見る
  - `updateBehavior()`: 角度を決める（T11〜T14）
  - `drawVirtualHead()`: 描く
- **完了の確認:** 動作は T15 と同じまま、`draw()` が数行になる

## フェーズ3：通信（ESP32 不要）

> ESP32 の代わりに、PC 上で「代役の WebSocket サーバー」を動かして通信を確認する。

### [ ] T17 送る角度を決める関数を作る

- **やること**
  1. `sendAngle(angle)` という関数を作り、中身はまず `console.log(angle)` だけにする
  2. 角度を整数に丸め、**前回と違うときだけ** 呼ぶようにする
- **完了の確認:** Console に角度が流れるが、首が止まっているときは出力が止まる

### [ ] T18 送信の間隔を間引く

- **なぜ:** 毎フレーム（約30回/秒）送ると、ESP32 の処理が追いつかなくなる
- **やること:** 前回の送信から 50ms 以上経っているときだけ送る
- **完了の確認:** Console の出力が1秒間に20回以下になる

### [ ] T19 代役の WebSocket サーバーを作る

- **やること**
  1. `pc/mock-server/` で `npm init -y` と `npm install ws` を実行する
  2. `server.js` に、ポート 81 で待ち受け、受け取ったメッセージを表示するだけのサーバーを書く
  3. `node server.js` で起動する
- **完了の確認:** ターミナルに「待ち受け中」のメッセージが出る
- **ポイント:** ポート 81 にするのは、後で ESP32 に入れるサーバーと同じ番号にしておくため。ポート番号の制限で起動できない場合は 8081 などに変える

### [ ] T20 p5.js から代役サーバーにつなぐ

- **やること**
  1. `sketch.js` で `new WebSocket("ws://localhost:81")` を作る
  2. `sendAngle()` の中で `socket.send(String(angle))` する
- **完了の確認:** 首を動かすと、代役サーバーのターミナルに角度が表示される

### [ ] T21 接続が切れても壊れないようにする

- **やること**
  1. 接続中かどうかを `socket.readyState` で確認してから送る
  2. 切断されたら 3秒後に再接続する
  3. 画面の隅に「接続中 / 切断」を表示する
- **完了の確認:** 代役サーバーを止めると「切断」になり、再起動すると自動で「接続中」に戻る

### [ ] T22 接続先を1か所で切り替えられるようにする

- **やること:** 接続先 URL を `sketch.js` の先頭の定数 `WEBSOCKET_URL` にまとめる
- **完了の確認:** 定数を1つ書き換えるだけで接続先が変わる（後で ESP32 の IP アドレスに変えるため）

## フェーズ4：シミュレータで ESP32 を書く（ESP32 不要）

> [Wokwi](https://wokwi.com/) は、ブラウザ上で ESP32 とサーボを動かせる無料のシミュレータ。
> ESP32 側のプログラムを、実機が届く前に書いて確かめておく。

### [ ] T23 Wokwi で ESP32 とサーボの回路を作る

- **やること**
  1. Wokwi で「ESP32」の新規プロジェクトを作る
  2. 部品追加（＋ボタン）から「Servo」を追加する
  3. サーボの信号線を GPIO 13、電源を 5V（VIN）、GND を GND につなぐ
- **完了の確認:** 画面上で ESP32 とサーボが線でつながっている

### [ ] T24 サーボを往復させる

- **やること**
  1. ライブラリに `ESP32Servo` を追加する
  2. 0° → 180° → 0° とゆっくり往復させるプログラムを書く
- **完了の確認:** 再生ボタンを押すと、画面上のサーボが往復する

### [ ] T25 シリアルで角度を受け取ってサーボを動かす

- **やること**
  1. `Serial.readStringUntil('\n')` で1行読み、`toInt()` で数値にする
  2. その角度に `servo.write()` する
- **完了の確認:** Wokwi のシリアルモニタに `120` と入力すると、サーボが 120° に動く
- **ポイント:** 後で受け取り口を WebSocket に変えても、「文字列 → 角度 → サーボ」の部分はそのまま使える。この部分は `applyAngleCommand(String text)` のような関数に分けておく

### [ ] T26 おかしな値を無視する

- **やること**
  1. 角度を `constrain()` で 30〜150° に制限する
  2. 数字でない文字列は無視する
- **完了の確認:** `abc` や `999` を送っても、サーボが変な動きをしない
- **なぜ:** 実機では、範囲外の角度でサーボや機構を壊すことがあるため

### [ ] T27 コードを保存する

- **やること:** Wokwi のコードを `esp32/looking_animal/looking_animal.ino` にコピーして保存し、コミットする
- **完了の確認:** リポジトリに `.ino` ファイルが入っている

## フェーズ5：実機で動かす（ここから ESP32 が必要）

### [ ] T28 Arduino IDE の準備をする

- **やること**
  1. Arduino IDE をインストールする
  2. 「Arduino IDE > 設定 > 追加のボードマネージャのURL」に ESP32 のURLを追加する
  3. 「ツール > ボード > ボードマネージャ」で「esp32 by Espressif Systems」をインストールする
- **完了の確認:** 「ツール > ボード」に「ESP32 Dev Module」が表示される

### [ ] T29 ESP32 を接続して LED を点滅させる

- **やること**
  1. USB-C ケーブルで ESP32 を Mac につなぐ
  2. 「ツール > ポート」で ESP32 のポート（`/dev/cu.usbserial-...` など）を選ぶ
  3. GPIO 2 の LED を点滅させる（Lチカ）プログラムを書き込む
- **完了の確認:** 基板の `IO2` の LED が点滅する
- **詰まったら:** ポートが出ないときは、ケーブルがデータ通信に対応しているか確認する。書き込みが始まらないときは、`BOOT` ボタンを押しながら書き込む

### [ ] T30 実機のサーボを配線して往復させる

- **やること**
  1. サーボの信号線を GPIO 13 に、電源を外部 5V 電源に、GND を外部電源と ESP32 の両方につなぐ
  2. T24 の往復プログラムを書き込む
- **完了の確認:** 実物のサーボが往復する
- **注意:** 配線を変えるときは、必ず USB と外部電源を抜いてから作業する

### [ ] T31 シリアルで実機のサーボを動かす

- **やること:** T27 で保存したプログラムを書き込み、「ツール > シリアルモニタ」から角度を送る
- **完了の確認:** `60` や `120` を送ると、実物のサーボがその角度に動く

### [ ] T32 Wi-Fi に接続する

- **やること**
  1. `esp32/looking_animal/secrets.sample.h` を `secrets.h` にコピーし、SSID とパスワードを書く（手順は [README](./README.md#wi-fi-の接続情報)）
  2. `WiFi.begin()` で接続し、接続できたら IP アドレスをシリアルに表示する
- **完了の確認:** シリアルモニタに `192.168.x.x` のような IP アドレスが表示される
- **注意:** ESP32 は 2.4GHz の Wi-Fi にしかつながらない。5GHz の SSID は使えない

### [ ] T33 ESP32 を WebSocket サーバーにする

- **やること**
  1. ライブラリマネージャで `WebSockets`（作者: Markus Sattler）をインストールする
  2. ポート 81 で待ち受け、受け取ったメッセージをシリアルに表示する
- **完了の確認:** ブラウザの Console で `new WebSocket("ws://<ESP32のIP>:81").onopen = () => console.log("ok")` を実行すると `ok` と出る

### [ ] T34 受け取った角度でサーボを動かす

- **やること:** WebSocket で受け取った文字列を、T25 で作った `applyAngleCommand()` に渡す
- **完了の確認:** Console から `socket.send("120")` すると、サーボが動く

### [ ] T35 通しで動かす 🎉

- **やること**
  1. `sketch.js` の `WEBSOCKET_URL` を `ws://<ESP32のIP>:81` に書き換える
  2. カメラの前で左右に動く
- **完了の確認:** **実物の首が、こちらを向く**
- **記録:** この瞬間を動画に撮って [media/](./media/) に保存する

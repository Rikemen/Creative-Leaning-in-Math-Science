Phase 5 — ESP32とサーボを実際に動かす

実機では、プログラムの間違いだけでなく、電源不足・配線ミス・機構の衝突が起こります。1つずつ単体確認し、どの境界まで動いたかを記録します。

ESP32 実機外部5V必須T30・T31・T35確認待ち

サーボは外部5V、GNDは共通

ESP32 GPIO 13 ───────── サーボ信号線
外部5V電源 ＋ ───────── サーボ電源線
外部5V電源 GND ──┬──── サーボGND線
                   └──── ESP32 GND
PCのUSB ─────────────── ESP32
重要配線変更時はUSBと外部電源を両方外します。外部電源のプラスはサーボだけへつなぎ、ESP32の3V3・5V・VINへはつなぎません。GNDだけを共通にします。

電気と信号は別の役割

外部5Vは「力」

サーボ内部のモーターを回す電流を供給します。電流不足は振動やESP32再起動の原因になります。

GPIO 13は「命令」

わずかな信号で目標角度を伝えます。サーボの電力を供給する線ではありません。

通し確認までの境界

  1. ESP32だけが動く（Lチカ）。
  2. サーボだけが往復する。
  3. シリアル文字で角度を指定できる。
  4. Wi-Fiへ接続してIPが出る。
  5. WebSocketで角度を受け取れる。
  6. カメラの顔位置で実物が動く。

失敗したら、最後に成功した境界へ戻ります。

各カードのステータスはDEVLOGに合わせています。確認待ちの項目は、実物で成功条件を観察するまで完了にはしません。

T28Arduino IDEを準備する 完了

  1. 追加のボードマネージャURLへESP32安定版URLを登録する。
  2. esp32 by Espressif Systemsを導入する。
  3. ESP32ServoとWebSocketsを導入する。
  4. ボードでESP32 Dev Moduleを選ぶ。
完了の確認「ツール → ボード」にESP32 Dev Moduleが表示される。

T29ESP32のLEDを点滅させる 完了

const int LED_PIN = 2;

void setup() {
  pinMode(LED_PIN, OUTPUT);
}

void loop() {
  digitalWrite(LED_PIN, HIGH);
  delay(500);
  digitalWrite(LED_PIN, LOW);
  delay(500);
}
最初にLチカする理由USBケーブル、ポート、ボード設定、書き込み手順をモーターと切り離して確認できます。
完了の確認基板のIO2 LEDが0.5秒ごとに点滅する。

T30実機サーボを往復させる 確認待ち

  1. 電源を外してGPIO 13・外部5V・共通GNDを配線する。
  2. 首の機構を外すか、十分な可動空間を確保する。
  3. servo/servo.inoを書き込む。
  4. 外部5V電源を入れる。
すぐ電源を切る症状動きが引っ掛かる、異音が続く、配線やサーボが熱い場合は、外部5VとUSBを両方外します。
完了の確認実物のサーボが30°〜150°をゆっくり往復する。

T31シリアルで実機を動かす 確認待ち

  1. looking_animal.inoを書き込む。
  2. シリアルモニタを115200 baud、行末New Lineにする。
  3. 60と120を送る。
完了の確認サーボが指定角度へ動き、Moving to angle: 60と表示される。

T32ESP32をWi-Fiへ接続する 完了

#include "secrets.h"

WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
while (WiFi.status() != WL_CONNECTED) {
  delay(500);
  Serial.print(".");
}
Serial.println(WiFi.localIP());

secrets.sample.hを初回だけsecrets.hへコピーし、2.4GHz帯のSSIDとパスワードを設定します。

秘密情報secrets.hはGitへコミットしません。見本ファイルだけを共有します。
完了の確認192.168.x.xのようなIPアドレスが表示される。

T33WebSocketサーバーを開始する 完了

WebSocketsServer webSocket(81);

void setup() {
  webSocket.begin();
  webSocket.onEvent(webSocketEvent);
}

void loop() {
  webSocket.loop();
}
loop()で監視ESP32は繰り返し新しい接続や受信データを確認します。長いdelay()を入れると通信への反応が遅れます。
完了の確認シリアルへWebSocket server started on port 81と表示される。

T34受け取った角度でサーボを動かす 完了

case WStype_TEXT:
  String text = String((char *)payload);
  applyAngleCommand(text);
  break;
再利用WebSocketの受信データも、T25で作ったapplyAngleCommand()へ渡します。入口が変わっても角度チェックは同じです。
完了の確認ブラウザから120を送ると、実物のサーボが120°へ動く。

T35カメラから実物まで通して動かす 確認待ち

  1. PCとESP32を同じネットワークへつなぐ。
  2. sketch.jsのWEBSOCKET_URLへESP32のIPとポート81を設定する。
  3. カメラ画面を開き、右上が「🟢 接続中」になることを確認する。
  4. 顔を左右へ動かす。
const WEBSOCKET_URL = "ws://192.168.x.x:81";
完了の確認画面の仮想の首と実物のサーボが顔を追い、顔が消えると約2秒後に90°へ戻る。

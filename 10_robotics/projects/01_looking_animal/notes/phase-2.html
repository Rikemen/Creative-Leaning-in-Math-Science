Phase 2 — 画面の中の仮想の首

実機をつなぐ前に、画面上の線と円を「仮想の首」として動かします。速く安全に試行錯誤し、気に入った動きだけをサーボへ送れる設計です。

ESP32 不要行動設計DEVLOG 完了

0〜1を30°〜150°へ写す

顔位置0を30°、1を150°へ対応させ、その間を同じ割合で割り当てます。中央の0.5は90°です。

0.0  →  30°
0.5  →  90°
1.0  → 150°
なぜ0°〜180°を使わない？サーボの物理端では内部ギアや取り付け機構へ負荷がかかることがあります。両端に30°の余裕を残します。

lerp()で少しずつ近づく

p.lerp(現在, 目標, 0.1)は、現在値から目標値までの距離の10%だけ進んだ値を返します。毎フレーム繰り返すと、最初は大きく、近づくほど小さく動きます。

0.02 のんびり

目標までの2%ずつ。おっとりした印象になります。

0.3 機敏

30%ずつ近づくため反応が速く、少し機械的になります。

時間を状態として覚える

firstSeenAtは顔を初めて見た時刻、lastSeenAtは最後に見た時刻です。現在時刻millis()との差を使えば、処理を止めずに「0.5秒待つ」「2秒後に戻る」を同時に扱えます。

このフェーズでは「見つけた顔」から「首の動き」までを、描画・角度計算・時間・UIに分けて作ります。

T10仮想の首を描く

キャンバス下中央を首の付け根にし、90°で正面を向くよう描画角を補正します。

p.push();
p.translate(p.width / 2, p.height);
p.rotate(headAngle - 90);
p.line(0, 0, 0, -120);
p.circle(0, -120, 60);
p.pop();
座標変換translate()は回転の中心を移動し、rotate()はその後に描く首を回します。サーボの90°を、画面の真上0°に合わせるため90を引きます。
完了の確認headAngleを書き換えると、線と円の向きが変わる。

T11顔の位置を角度に変換する

targetAngle = p.map(targetX, 0, 1, 30, 150);

map()の引数は「元の値、元の最小、元の最大、新しい最小、新しい最大」です。

完了の確認顔を左右へ動かすと、仮想の首が30°〜150°で追いかける。

T12動きを滑らかにする

headAngle = p.lerp(
  headAngle,
  targetAngle,
  lerpSlider.value()
);
2つの角度targetAngleは行き先、headAngleは現在地です。分けることで、瞬間移動ではなく途中の動きを作れます。
完了の確認素早く顔を動かしても、首がなめらかに追従する。

T13見失ってから正面へ戻す

if (targetFace) {
  lastSeenAt = p.millis();
} else if (p.millis() - lastSeenAt > 2000) {
  targetAngle = 90;
}
引き算で経過時間現在時刻から最後に見た時刻を引くと、見失ってから何ミリ秒経ったか分かります。2000msは2秒です。
完了の確認顔が消えてもすぐには動かず、2秒後にゆっくり90°へ戻る。

T14気づくまでの「間」を入れる

if (!isFacePresent) {
  firstSeenAt = p.millis();
  isFacePresent = true;
}

if (p.millis() - firstSeenAt > 500) {
  targetAngle = p.map(targetX, 0, 1, 30, 150);
}
真偽値isFacePresentは「顔がいる／いない」の2状態を覚えるtrueかfalseの変数です。新しく現れた瞬間だけ時刻を保存できます。
完了の確認画面へ入った直後は止まり、約0.5秒後に首が動き始める。

T153つの値をスライダーで調整する

lerpSlider = p.createSlider(0.01, 1.0, 0.1, 0.01);
returnDelaySlider = p.createSlider(0, 5000, 2000, 100);
reactionDelaySlider = p.createSlider(0, 2000, 500, 50);

それぞれ「最小、最大、初期値、変化幅」です。動かしながら性格を比較します。

完了の確認スライダーを動かすと、滑らかさ・戻る時間・気づく間がその場で変化する。

T16役割ごとの関数へ整理する

p.draw = () => {
  const targetFace = detectFace();
  updateBehavior(targetFace);
  drawVirtualHead();
  drawFaceCenterLabel();
  drawConnectionStatus();
  sendAngle(headAngle);
};
分ける理由見る・考える・描く・送るを別関数にすると、どこを直すべきかが分かりやすくなります。これはハードウェアの切り分けと同じ考え方です。
完了の確認動作は変わらず、draw()が処理の順番だけを読める短い形になる。

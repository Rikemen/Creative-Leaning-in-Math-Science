# DEVLOG：距離によって態度が変わるライオン

上から順に1つずつ進め、終わったら `[ ]` を `[x]` にする。

## 進め方のルール

- **1タスク = 1つの「動いた！」を確認する。** 確認できたら次へ進む。
- **動いたらコミットする。** 壊しても1つ前に戻れるようにする（例: `git commit -m "T08 距離から3状態の判定ロジックを実装"`）。
- **詰まったら15分で切り上げる。** 何が起きたかをメモし、ヒントを調べるか相談する。
- **ESP32 実機が届くまではフェーズ0〜4を進める。** 実機が必要なのはフェーズ5からだけ。

## 全体の流れ

```text
フェーズ0  PC側モック        p5.js で画面演出・擬似音声・代役サーバーを作る
フェーズ1  センサー＆状態    ESP32 で距離計測・状態遷移（ステートマシン）・ノイズ除去
フェーズ2  シミュレータ      Wokwi でサーボモーター連動の回路と制御を書く
フェーズ3  通信              Wi-Fi & WebSocket で状態送信（エッジ検出）
フェーズ4  PC×ESP32 結合     シミュレータとブラウザを繋いで通しで動かす
--------------------------- ここから ESP32 実機が必要 ---------------------------
フェーズ5  実機配線＆調整    ESP32 + HC-SR04 + サーボの実機配線と実空間チューニング
フェーズ6  仕上げ            ライオンの外装造形・展示調整・記録動画
```

## フェーズ0：PC側モック＆演出開発（ESP32 不要）

> ESP32 がなくても進められるブラウザ側の演出を先行して作成・確認します。

### [x] T01 p5.js のキャンバスと音声用オーバーレイを作る

- **なぜ:** 現代のブラウザはユーザー操作（クリック）がないと音声を自動再生できない制限があるため
- **やること**
  1. `pc/index.html` と `pc/sketch.js` を作成する
  2. クリックで非表示になる `#start-overlay` を用意し、クリック時に `userStartAudio()` を呼ぶ
- **完了の確認:** 画面をクリックするとオーバーレイが消え、p5.js のキャンバスが現れる

### [x] T02 3つの状態（SLEEPING, ALERT, ROARING）を描画する

- **やること**
  1. `sketch.js` に `lionState` 変数を用意する
  2. `SLEEPING`（遠距離：青背景・😴）、`ALERT`（中距離：橙背景・🤨）、`ROARING`（近距離：赤背景・🦁＋揺れ演出）を `draw()` で切り替え描画する
- **完了の確認:** 変数の値を手動で書き換えると、それぞれの画面表示に切り替わる

### [x] T03 状態変化のエッジ検出と擬似咆哮音（オシレーター）を鳴らす

- **なぜ:** `ROARING` 状態の間ずっと鳴らし続けると音が重なって不快なノイズになるため、「入った瞬間」だけ鳴らす
- **やること**
  1. `prevState` を用いて、`lionState !== prevState && lionState === 'ROARING'` の瞬間（エッジ）を検出する
  2. `p5.Oscillator('sawtooth')` と `p5.Envelope` で擬似的な低い咆哮音を再生する
- **完了の確認:** `ROARING` に切り替わった瞬間だけ「ガオッ」という低音が1回鳴る

### [x] T04 PC側の代役 WebSocket サーバーを作る

- **やること**
  1. `pc/mock-server/` で `npm init -y` と `npm install ws` を実行する
  2. `server.js` にポート 8080 で待ち受け、3秒ごとに状態を順繰りに送信するサーバーを書く
- **完了の確認:** `node server.js` を実行すると「Mock WebSocket server started」と表示される

### [x] T05 p5.js と代役サーバーを繋いで自動変化を確認する

- **やること**
  1. `sketch.js` で `ws://localhost:8080` へ接続する
  2. メッセージ受信時に `lionState` を更新し、切断時の自動再接続を入れる
- **完了の確認:** ブラウザ画面が 3秒ごとに SLEEPING → ALERT → ROARING と自動で切り替わり、ROARING 時に音が鳴る

### [ ] T06 本物のライオンの咆哮音（mp3）に差し替える（任意）

- **やること**
  1. フリー音源等からライオンの鳴き声ファイルを入手し、`pc/assets/roar.mp3` に配置する
  2. `preload()` で `loadSound()` し、オシレーターの代わりに音声を再生する
- **完了の確認:** `ROARING` になった時に本物の鳴き声がクリアに再生される

## フェーズ1：ESP32 センサーと状態判定ロジック（ESP32 実機または Wokwi）

> 超音波センサーで距離を測り、安定して 3 つの状態へ分類するロジックを固めます。

### [x] T07 超音波センサー（HC-SR04）の距離読み取り

- **やること**
  1. `esp32/lion_distance/lion_distance.ino` に Trig（GPIO 5）と Echo（GPIO 18）を設定する
  2. 10μs のパルスを出力し、`pulseIn` で反射時間を計測して距離（cm）を計算する
- **完了の確認:** シリアルモニタに `Distance: xx.x cm` が 0.5秒ごとに流れる

### [ ] T08 距離から 3 つの状態への分類ロジックを実装する

- **やること**
  1. 状態を表す `enum LionState { SLEEPING, ALERT, ROARING };` を定義する
  2. 距離に応じて状態を分類する（例: 100cm未満 → `ROARING`, 100〜200cm → `ALERT`, 200cm以上 → `SLEEPING`）
  3. シリアルモニタに現在の状態名を出力する
- **完了の確認:** センサーの前に手を近づけたり遠ざけたりすると、シリアルモニタの状態表示が変わる

### [ ] T09 センサーノイズ対策①（移動平均フィルタの導入）

- **なぜ:** 超音波センサーはたまに測定不能（0cmや極端な値）になるノイズが発生し、誤動作の原因になるため
- **やること**
  1. 直近 5 回分の測定値を配列に保持し、平均値を計算する関数 `getFilteredDistance()` を作る
  2. 0 や 400cm 以上の異常値は前回の正常値で補完する
- **完了の確認:** センサーの前に一瞬ノイズが入っても、距離の急激な跳ね上がりが抑えられる

### [ ] T10 センサーノイズ対策②（ヒステリシスによるチャタリング防止）

- **なぜ:** 境界線（例: ちょうど 100cm 付近）で立ち止まった時に、状態が激しく交互に入れ替わるのを防ぐため
- **やること**
  1. 境界に ±5cm の遊び（ヒステリシス）を持たせる（例: ROARINGに入るのは 95cm以下、抜けるのは 105cm以上）
- **完了の確認:** 境界付近に手を置いても、状態がパタパタと頻繁に切り替わらなくなる

### [ ] T11 状態遷移時のエッジ検出（変化時のみ通知）

- **やること**
  1. `LionState prevState` を保持し、状態が変わった瞬間だけシリアルモニタに `State changed: ROARING` と出力する
- **完了の確認:** 同じ状態にとどまっている間はシリアル出力が静かになり、状態が変わった瞬間だけログが出る

## フェーズ2：Wokwi シミュレータでサーボ制御（ESP32 不要）

> ブラウザ版 Wokwi (https://wokwi.com) を使い、距離センサーとサーボの連動をシミュレーションします。

### [ ] T12 Wokwi で ESP32 + HC-SR04 + サーボの回路を作る

- **やること**
  1. Wokwi で ESP32 プロジェクトを作成し、`HC-SR04` と `Servo` を追加する
  2. 配線: Trig → GPIO 5, Echo → GPIO 18, サーボ信号線 → GPIO 13, 各電源と GND を接続する
- **完了の確認:** Wokwi の配線画面で各パーツが結線されている

### [ ] T13 サーボモーターの動作確認

- **やること**
  1. `ESP32Servo` ライブラリを追加し、`setup()` でアタッチする
  2. 0° → 90° → 180° と動かすテストコードを動かす
- **完了の確認:** Wokwi 上でサーボのホーンが動く

### [ ] T14 状態に応じたサーボの目標角度を設定する

- **やること**
  1. `SLEEPING`: 首を下げる（例: 30°）
  2. `ALERT`: 首を上げて前を見る（例: 90°）
  3. `ROARING`: 首を大きく動かす、または口を開く（例: 150°）
- **完了の確認:** 状態が変わるとサーボがそれぞれの指定角度へ回転する

### [ ] T15 距離スライダーを動かして一連の動作を確認する

- **完了の確認:** 距離に応じてシリアルモニタの状態が切り替わり、サーボの角度が連動する
- **コード保存:** 完成したコードを `esp32/lion_distance/lion_distance.ino` にコピーして保存・コミットする
